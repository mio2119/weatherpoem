# WeatherPoem 公开分发、撤回与恢复演练

更新时间：2026-07-24  
适用基线：WeatherPoem 0.2.0 / `trial` / `unsigned-trial`  
当前结论：演练方案已就绪，尚无 production 发布物和正式 HTTPS 下载地址。

机器计划位于 `review/public-distribution-rehearsal-plan.json`。运行
`npm run distribution:plan:check` 可确认它仍绑定当前三项发布物、校验文件、
内容撤回报告和事故 Runbook。

## 目标

这项演练要证明的不只是“文件能上传”，而是完整闭环：

1. 三项签名 production 发布物可从批准的 HTTPS 主机独立重下；
2. 最终主机、重定向、尺寸、SHA-256、Authenticode、时间戳和证书允许列表一致；
3. 清单和产物不会因部分上传或 CDN 旧缓存产生混合版本；
4. 单首错误内容可以在线/离线撤回且修订号不能回退；
5. 错误二进制可以停止分发和更新，并能以前向修复版本恢复；
6. 每个上传、切换、撤回、通知和恢复动作都有具名时间线。

## 安全发布顺序

1. 在受控 Windows 发布机生成并复核 production 清单；
2. 上传不可变、版本化的 portable、NSIS 和 MSI，暂不切换 `latest`；
3. 从独立设备重下并验证 TLS、重定向、哈希和 Authenticode；
4. 执行安装、用户数据保留和 signed updater 联合检查；
5. 原子发布版本清单与校验文件，最后切换 `latest`/更新元数据；
6. 公开后再次重下并记录证据；
7. 演练内容撤回；
8. 演练二进制撤回和 CDN 缓存处理；
9. 用更高补丁版本完成前向修复；
10. 复验恢复版本并完成具名复盘。

任何一步失败都停止后续切换，不能在旧清单指向新文件或新清单指向缺失文件时继续。

## 十个场景

演练固定包含：

- 三项正式发布物公开重下；
- 哈希不一致；
- 签名、时间戳或证书不受信；
- 错误主机、重定向或 TLS 失败；
- 部分上传或缓存旧清单；
- 错误内容在线撤回；
- 错误内容离线撤回；
- 二进制紧急撤回；
- 前向修复与恢复发布；
- 审计与通知闭环。

每项必须填写执行人、时间、设备、网络环境、最终 URL、响应头摘要、文件哈希、
签名结果、截图/日志定位和结论。外部定位只允许无凭据 HTTPS 地址；私有访问令牌、
CDN 密钥和完整用户数据不得写入仓库。

## 二进制撤回

撤回动作按风险顺序执行：

1. 冻结新发布并保留所有现有文件、清单和日志；
2. 停止 updater 元数据和 `latest` 指针；
3. 移除公开下载入口并按供应商流程清除 CDN 缓存；
4. 发布影响范围、临时措施和下一次更新时间；
5. 不远程删除已安装应用，不让客户端进入无法启动状态；
6. 构建更高补丁版本，重新完成签名、上传和独立重下；
7. 恢复分发并完成事故复盘。

内容撤回继续使用现有按 `workId` 的全局暂停、修订防回退和离线缓存机制；它不能
替代二进制撤回。
