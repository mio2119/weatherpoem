# WeatherPoem P0/P1 事故响应 Runbook

更新时间：2026-07-24

## 1. 使用边界

本手册覆盖错误内容、预警源失效、重复弹出、无法启动、更新或数据损坏等 P0/P1
事故。当前文件定义可执行动作，但没有替项目组织填写真实姓名、电话和值班渠道。
项目发起人必须在 RQT-18 决策记录中指定责任人，演练后按
`review/evidence/README.md` 形成具名证据。

## 2. 等级与响应目标

| 等级 | 示例 | 首次响应 | 首要目标 |
| --- | --- | ---: | --- |
| P0 | 错误原文/作者被大范围传播；严重预警期间仍推送浪漫化内容；更新破坏用户数据 | 立即 | 停止传播、保护人身与数据安全 |
| P1 | 多数用户无法启动；重复自动弹出；预警网关持续失效；内容包或更新签名异常 | 4 小时内 | 降级、暂停或恢复上一稳定版本 |

任何人发现可能的 P0 都可以触发响应。只有发布负责人可以发布二进制，内容负责人和
第二批准人共同授权内容撤回；安全负责人有权要求保持全局暂停。

## 3. 启动事故

1. 创建组织批准的事故编号，记录发现时间、报告人、版本和影响范围；
2. 保存最小证据：截图、作品 ID、内容版本、应用版本、预警/网关状态和复现步骤；
3. 不把密钥、精确位置、收藏、历史或完整用户数据库放入工单；
4. 由事故指挥角色判定 P0/P1，指定内容、发布、数据、安全和沟通负责人；
5. 在时间线中记录每个决定、批准人、执行人和 UTC/带时区时间。

## 4. 错误内容撤回

1. 内容负责人核对作品 ID、错误字段和权威证据；
2. 运维读取当前清单，保留全部既有 ID，将 `revision` 加一；
3. P0 大范围风险设置 `suspendRecommendations: true`；单首问题只追加对应 ID；
4. 内容负责人和第二批准人复核 JSON，不在清单中写事故原因或用户信息；
5. 通过受控 HTTPS 网关原子发布，禁止覆盖成更低修订；
6. 从网关外部重新下载并核对内容版本、修订号、响应头和 TLS；
7. 在试点客户端重新打开托盘，确认正文消失并显示“今日内容正在校正”；
8. 断开网络再次打开，确认最后有效撤回仍生效；
9. 修改源码审核状态为 `retracted`，更新内容版本并启动永久修订；
10. 对外更正只说明受影响内容、处理状态和用户需要采取的动作，不暴露内部凭据。

恢复展示必须发布更高修订号。不得复用旧修订，也不得通过删除本地缓存强制恢复。

## 5. 正式预警源失效

1. 外部监控区分“合法空预警响应”和超时、5xx、授权失败或过期数据；
2. 保留基础天气安全代理，但不得将其表述为官方预警；
3. 若存在严重天气或无法判断安全影响，使用内容控制清单设置
   `suspendRecommendations: true`；
4. 检查网关授权、证书、上游许可、城市映射和 CSP，不把供应商密钥发给客户端；
5. 恢复后先验证一条无预警响应和一条仍有效预警，再以更高修订解除全局暂停；
6. 保存上游状态、客户端降级截图、恢复时间和责任人。

## 6. 应用或更新故障

- 停止上传和公开下载，保留已发布文件与 SHA-256；
- 未接入 Tauri updater 前，按 `docs/WINDOWS_MANUAL_EVIDENCE.md` 使用已验证的
  上一版 NSIS 人工恢复，不宣称自动回滚；
- 不删除 `%APPDATA%` 或 `%LOCALAPPDATA%` 中的用户数据来解决启动问题；
- 只有卸载注册项已消失时，清理脚本才可以删除精确匹配的测试安装目录；
- 重新发布必须重新生成签名、时间戳、哈希、安装生命周期和设备证据。

## 7. 受控演练

自动预演：

```powershell
cd E:\weatherpoem
npm run content:withdrawal:drill
npm run content:withdrawal:check
```

具名客户端演练必须在专用试点账号和非生产清单上执行：

1. 记录初始修订号和一首当前展示作品；
2. 发布更高修订并撤回该作品；
3. 验证首页、阅读页和收藏列表不再传播正文；
4. 验证校正提示与替换作品；
5. 断网验证缓存，发布低修订和同修订冲突验证拒绝；
6. 发布更高修订恢复清单；
7. 检查用户设置、收藏 ID、历史和反馈没有被删除；
8. 由执行人、观察人和批准人签署演练证据。

真实生产网关不得为了演练撤回正式用户正在使用的内容，除非已有批准的演练窗口和
通知方案。

## 8. 通知模板

首次通知：

> WeatherPoem 正在处理一起【P0/P1】事件，影响范围为【版本/内容/服务】。
> 已于【时间】采取【暂停/撤回/回滚】措施。下一次更新不晚于【时间】。

恢复通知：

> 【事故编号】已于【时间】恢复。受影响范围为【范围】，用户数据【未受影响/影响说明】。
> 更正版本或内容修订为【标识】。后续将完成复盘并跟踪改进项。

## 9. 关闭与复盘

关闭前必须确认安全影响消失、撤回或回滚证据可访问、用户数据边界未破坏、监控恢复、
通知已发送。两个工作日内完成根因、时间线、发现缺口、有效/无效措施、责任人与截止
日期。P0/P1 未完成复盘和行动项登记时不得仅以“已恢复”关闭。
