## 为什么不能用浏览器缩放代替系统 DPI

Windows 的 125%/150%/200% 缩放会同时影响 WebView2 的设备像素比、
原生窗口坐标、托盘、窗口定位和多显示器转换。浏览器里改变 CSS 视口或页面
缩放只能观察一部分布局结果，不能证明：

- 应用是否出现在正确显示器的右下角；
- 混合 DPI 显示器之间移动后是否重新定位；
- 标题栏、托盘菜单和 WebView2 是否清晰；
- 开机自启时窗口是否被全屏演示或专注模式错误打断；
- NSIS/MSI 安装、升级、卸载是否留下自启项或本地文件。

因此这些项目保持为真实设备发布门禁，而不是写成“已通过”。

## 执行方式

计划与结果保存在 `review/device-matrix-plan.json`。每个用例完成后填写：

- `executor`：真实执行人；
- `executedAt`：ISO 8601 时间；
- `evidence`：截图、录屏、日志或缺陷单的可访问路径；
- `result`：`passed`、`failed` 或 `blocked`；
- `issue`：失败/阻塞原因；通过时必须为空。

契约检查：

```powershell
cd E:\weatherpoem
npm run device:matrix:check
npm run release:verify:manual-windows
npm run release:verify:upgrade
```

第二个命令只有在管理员 MSI 和两次真实重启报告都已生成时才会通过；它不会自动
改变九个用例的结果。第三个命令只有升级回滚报告已生成时才会通过。执行人仍须
逐项填写具名证据。

正式公开发布前，九个 `requiredCases` 必须全部为 `passed`。浏览器矩阵通过、
开发机冒烟通过或“未发现问题”都不能自动替代具名设备证据。
