版本：1.6；制定日期：2026-10-12；进度核对：2026-10-13；用途：供后续 AI 编码任务逐阶段执行、提交证据和自验收。实际开发目录始终是 `E:\weatherpoem`。`D:\纯净工作台` 只承担控制与独立审计，不存放本项目源码。

本方案根据 [产品体验审查](./PRODUCT_EXPERIENCE_AUDIT_2026-10-12.md)、当前 Vue 3/Tauri 2 实现和项目发起人的新想法制定。它同时是目标规范和后续执行入口；已实施内容、仍缺的证据以第七节及 `review/redesign/` 的逐任务记录为准，不能因写在计划里就视为验收通过。当前 `0.2.0` 未签名内部试用候选及其发布证据保留为旧基线；新构建应使用可区分的候选身份，旧哈希不能证明新候选通过。七天长测已按项目决定跳过，RQT-13 完整门禁继续保持 `partial`。

## 一、产品决定与体验目标

### 1. 用户已经确认的方向

1. 目标用户：有文化基础、但在大学日常中逐渐失去接触传统文化机会的学生。
2. 每天打开电脑自然遇到一首诗，优先级为传统节日 > 当地天气 > 节气；重要事件属于以后人工策展的独立能力。
3. 默认信息少，感兴趣时才展开原文、背景、注释和出处。
4. 诗句可选择自上而下的竖排阅读。
5. 背景动效与小组件帮助感知作品和环境。
6. 默认桌面小弹窗，允许放大、缩小和进入可调整尺寸的阅读状态。

### 2. 本方案暂定的实现决策

这些参数用于给 AI 一套可开发、可测试的目标；如真实内容排版和用户观察证明不合适，可以修改参数并记录依据，不应悄悄改变已确认的产品方向。

| 状态 | 初始建议 | 内容与行为 |
|---|---|---|
| 首次设置 | 使用能完整显示表单的窗口，允许滚动 | 明确确认城市；首次设置不受小诗笺高度限制。 |
| 桌面诗笺 | 首次建议约 392×320 逻辑像素，按实际内容在工作区内调整；用户可在小、中、大尺寸间切换 | 一首诗的一至两句完整节选、题名作者、一句简短理由、继续读/收起和轻量反馈；无需滚动才能读完主要内容。 |
| 展开阅读 | 初始约 560×720，受当前显示器工作区限制；支持拖动改变尺寸和最大化 | 全文、注释、时代背景、今日联系、可核查来源；可返回诗笺。 |
| 安全提醒/内容校正 | 根据真实文字长度单独适配 | 不能把预警、撤回说明压进无法阅读的短卡片，也不能被装饰动效弱化。 |

- 首次使用默认横排，竖排作为显眼但安静的切换项；记住用户选择。横排和竖排展示相同完整句子，DOM 与读屏顺序保持自然阅读顺序。
- 竖排是可选阅读方式，不预先认定一定比横排省空间。小窗必须用五言、七言、词及长节选分别试排；若竖排使诗句、标题或操作被挤压，应增高诗笺或回退横排，不通过缩小字号硬塞。
- 窗口尺寸与正文字号分别控制。用户选的小、中、大尺寸影响窗口；字号影响诗句和正文。展开阅读可拖动调整并记住上次的阅读尺寸。下次自动启动仍按用户选择的小诗笺尺寸出现。
- 默认动效为轻微；同时提供“静态”设置，系统减少动态效果时自动使用静态场景。诗文、按钮、注释本身保持稳定。隐藏到托盘时所有可循环动效停下。
- 环境美术根据真实可用的节日、天气、节气和作品意象生成。天气不可用时不把下雨/下雪画成当地实况；官方天气预警时暂停诗笺与装饰表现，保留安全提示优先级。
- 美术只使用项目已有资产或明确记录来源及使用权的新资产；优先 CSS/SVG 的低成本实现，新增依赖先核对 `package.json`、构建体积、许可和资源占用。

视觉制作时先统一一套基本规则：诗句在诗笺中优先试排约 22–26px，理由和可操作文字优先试排 13–14px，辅助标签优先试排 11–12px；最终取值以实际内容、对比度和窗口适配测试为准。背景与文字之间须有固定的安全阅读区域。同一画面最多突出一个主要意象和一个情境小组件。按钮图标的笔画与交互反馈采用统一规则。已有纸色、宋体阅读和朱红强调可作为起点，而不是强制所有情境都变成同一张画。

| 已知情境 | 初版视觉策略 | 真实性约束 |
|---|---|---|
| 节日与作品匹配 | 选一个可核查的节俗意象或色彩 | 只有当天确属该节日且作品确实关联时使用。 |
| 实际下雨/下雪 | 低对比水纹/留白中的细雪 | 只用新鲜或明确标为缓存的真实天气；不把诗中天气当作当地实况。 |
| 晴、云、夜 | 纸面光影或远景明暗变化 | 变化应缓慢且位于文字区外，不虚构温度或预警。 |
| 天气不可用 | 作品意象或抽象季节纹理 | 明示天气未更新，画面不声称当地正在下雨、下雪。 |
| 安全预警或内容撤回 | 静态、清晰的提示 | 停止常规诗境动效，保证提醒与处置入口优先。 |

### 3. 交互主路径

```text
开机自动启动 → 判断当天是否已处理、全屏/专注状态和安全提醒
             → 可出现时以不取焦点的桌面诗笺呈现
             → 用户阅读／收起／收藏／标记不贴合／每天换一次
             → 用户主动继续读 → 展开阅读窗 → 字号／横竖排／全文与小注
             → 返回诗笺或隐藏到托盘 → 手动再次打开时核对本地日期
```

若无法可靠判断全屏/演示状态，应采用保守的托盘保留路径并记录该情况；不得在此情况下把“全屏不打扰”标为已验证。自动出现与用户手动打开是不同的焦点策略：自动出现不取焦点，托盘主动打开可以取焦点。

禁止改动旧候选并沿用旧发布证据；若需要构建新 EXE，应先确认没有仍在运行的正式长测或被冻结的候选，再将所有新报告绑定到新 EXE 和安装包的 SHA-256。任何现有用户个人数据、安装状态、注册表自启动和系统显示设置都不能作为自动化测试耗材；使用隔离资料目录和专用测试账户。AI 可以自行建立隔离测试数据，不应擅自重启、安装、卸载或清理真实账户的数据。

## 四、逐项任务说明及通过条件

### T00｜建立改版基线与场景清单

**实施**：记录当前 `0.2.0` portable、NSIS、MSI 版本与哈希，检查现有测试和体验审查中的 E01–E16；分别保存现有首页、阅读、首次设置、设置、离线、安全提醒和内容撤回的观察结果。建立改版任务验收记录，标明“静态代码通过、原生 Windows 通过、人工未做”等真实状态。保留原始发布证据，不在方案阶段重建候选。

**A0 通过条件**：旧 EXE 和发布清单哈希与开始前一致；每个待修事项映射到本方案的 T 任务；Tauri 原生与浏览器/组件测试的覆盖范围标注清楚。若没有可用浏览器控制，可用现有 Vue 测试与原生窗口检查补足，留下未测说明。

### T01｜日期更新、换诗限次、展示历史

**实施**：统一所有每日行为的本地日期键；时间戳继续使用带时区含义的标准时间，但业务限次不截 UTC 日期。重新打开托盘、窗口重新可见、机器唤醒后核对当地日期；跨日选择新诗，同日保留已有诗。将“当天当前作品”和“每次实际展示事件”分开，保留被换掉的作品。迁移已有 SQLite/localStorage 数据时不能丢收藏或已保存设置。

**A1 通过条件**：

- 在北京时间 00:00、07:59、08:00 和 23:59 的受控时钟测试里，同一自然日只可主动换一次，次日恢复资格；其他时区也使用各自当地日期。
- 23:59 收起、次日重新打开显示次日日期及推荐；当天再次打开不额外自动弹出，不重复扣限次。
- 休眠/恢复、断网/联网、同日多次手动打开不抹掉收藏、反馈和当日已展示记录。
- 新历史记录包含当天原诗与替换诗；旧数据载入不报错，数据清除功能仍能删除两类新记录。

### T02｜推荐候选、重复控制与推荐理由

**实施**：在计分之前排除明显季节/场景冲突；对节日强关联设置可解释例外，不把所有含“春”的标题机械排掉。按节日 > 天气 > 节气选择主要关联；天气不可用时只用可验证的日历、季节或作品自身关联。内部 `spring/summer/autumn/winter` 只在模型层使用，界面显示中文。理由由完整语义单元组合，不截断句子，不出现双标点和无法解释的通用尾句。历史、作者和主题多样性用真实 120 首目录模拟，不预设 90 天一定可兑现；设计决定要解释为何选择新的避让窗口。反馈先影响作品，再以可撤销、有限影响的方式调整标签。

**A2 通过条件**：

- 回归：2026-01-14 小雨/多云不把只适用早春的作品直接当作当地冬季天气诗；节日和节气冲突有确定性排序；无候选时可安全降级或明确显示无诗，不把不合适作品硬推荐。
- 全 120 首在节日、天气、节气、离线四类理由中不出现英文枚举值、“。，”等错误、不完整句和虚构的当地天气。
- 对 30/60/90 天多组季节、天气与节日模拟，记录不同作品数、最短重复间隔、作者重复间隔和无法匹配天数；新规则须明显改善本轮“固定晴天60天仅23首”的基线，并避免同一作品约八天循环。具体目标由模拟分布支持，不能仅以单个测试样本宣布长期多样性通过。
- 单次“不太贴合”不会永久压低整个情绪/生活主题；撤销或过期后推荐恢复。理由文案与实际选择上下文一致。

### T03｜首次设置、偏好保存和失败反馈

**实施**：城市搜索无结果时显示支持范围与清晰的下一步，开始前明确显示最终所选城市；若提供离线体验，其天气不可用状态要如实展示。设置页草稿跨收藏/试点导航不静默消失，可选“即时保存简单偏好”或“显式保存/取消”，但同一页面遵循一种一致模型。自启动写入失败必须让用户知道真实系统状态。旧配置缺少新增字段时使用安全默认值，偏好重置应覆盖新增字段。

**A3 通过条件**：

- 搜索“深圳”等未支持城市、无结果、清空搜索、搜索后不选等路径不会悄悄以北京请求天气；用户知道实际城市和是否处于离线模式。
- 修改城市/主题/动画后去收藏再回来，选择保留或明确告知未保存；保存失败不显示“全部设置已保存”。
- 自启动被系统拒绝时，界面与系统实际状态一致；不通过测试脚本修改真实用户系统设置。
- 桌面 SQLite 初始化失败时，明确显示资料暂不可读并停止载入；不得无提示地切换到空白浏览器存储，让收藏和设置看似丢失。重试成功后清除旧错误。
- 键盘操作城市选项可看到焦点，单选组语义正确；旧 SQLite 和浏览器存储升级后能正常打开、保存、清除。

### T04｜窗口双状态与自动显示策略

**实施**：在现有单窗口 Tauri 壳上建立 `setup / glance / reading / safety` 显示状态；小诗笺与阅读窗切换时调整窗口尺寸、可调整性和位置，避免重复 WebView 或重置推荐。用户主动改变阅读窗大小后记录可复用的尺寸；下次自动出现仍默认小诗笺。为自动触发与手动打开建立不同的焦点策略，前台全屏/演示场景提供可验证的延迟或托盘策略。最小化、隐藏、第二实例和托盘菜单行为保持一致。

**A4 通过条件**：

- 原生 Windows 10/11 的可用环境中，自动展示不夺走正在输入的窗口焦点；手动从托盘打开后可键盘操作。若全屏识别不可靠，执行事先定义的托盘降级并留下证据。
- 诗笺→阅读→诗笺无闪屏、内容重载、收藏状态丢失；展开、缩小、多显示器切换与 DPI 变化后窗口完整位于当前工作区，无法在屏外找不到。
- 关闭到托盘不退出，同日自动启动抑制仍有效；安全提醒和撤回文案不被小窗裁掉。
- 用户无论何时都可从大窗返回诗笺；运行中改变窗口尺寸不会触发第二次推荐或重复计入展示。

### T05｜小诗笺的信息与操作位置

**实施**：第一眼突出完整节选和题名作者；日期、真实天气/节日/节气压成一条可理解的情境提示；理由保留一完整短句。继续读、收起和收藏始终可找，换一首/不太贴合可折叠到轻量次级操作，但不能藏到不可发现的区域。首页增加简洁收藏复访入口。当前的 `PoemCard.vue`、`WindowChrome.vue` 与 `styles.css` 增量调整，不一次重写所有页面。

**A5 通过条件**：

### T06｜竖排、横排与字号

**实施**：诗句支持横排和传统中文从上往下、列从右往左竖排；完整句不被拆断。小诗笺只竖排诗文，按钮、理由、日期与辅助文字保持易读横排。展开阅读可对原文切换排版；注释、背景和出处维持横排。采用单一语义文本顺序和两套视觉样式，检查 WebView2 竖排标点、引号、阿拉伯数字与长词标题。正文字号给出少量稳定档位，偏好本地保存；主题跟随系统时应对系统切换作出响应。

**A6 通过条件**：

### T07｜诗境背景、细微动效和小组件

**实施**：先做静态画面，再给少量场景增加局部动效。初版最多建立若干可重复使用的视觉主题，如清雨、水纹；晴日、微光；雪、留白；夜、远景。节日可在匹配且内容相关时取代一般天气作为主要画面；天气不可用时只做抽象季节气氛，不伪装成当地实时天气。小组件每次最多一个，例如节气印记或天气小景，具有明确含义；装饰资源不成为额外信息墙。设定统一字体、色阶、图标笔画、层次和安全文字区，浅色/深色各有静态帧。

**A7 通过条件**：

**A8 通过条件**：

## 八、给执行 AI 的任务卡与验收纪律

本节用于把第三、四节的要求变成一次可交接的工作任务，不替代各 T 项的详细通过条件。项目方每次指定一个任务编号或一个有共同退出条件的小批次；执行 AI 不得自行把“做了功能”“写了测试”“完成原生/人工验收”合并成一句“已完成”。A0–A9 可以在记录上游缺口的前提下做隔离探索，但不能越过依赖宣布整项通过；T10 的正式候选与发布门禁仍须等适用的上游节点签收。

### 1. 执行顺序与每阶段的产物

| 阶段 | 任务 | AI 应交付 | 本阶段签收条件 |
|---|---|---|---|
| 基础可信 | T00–T03 | 基线哈希、跨日/历史和推荐规则、首次设置与异常反馈；对应自动测试和隔离资料记录 | A0–A3 的适用子项均通过；明显错季、错误城市、丢设置或虚构天气为阻断。 |
| 日常体验 | T04–T06、T08 | 小诗笺/阅读窗状态、信息层级、横竖排与字号、展开阅读和收藏找回；真实窗口截图及键盘路径 | 主要诗句和操作在小窗可见，展开/返回不丢状态；未测的原生缩放和读屏不能提前标通过。 |
| 诗境美术 | T07 | 节日/天气/节气/离线的场景映射、浅深色静态帧、代表性短录屏、静/动资源对照和素材台账 | 场景不误称实况，装饰不遮字，减少动态与隐藏停机可验证；同机同诗境 60 秒资源目标达到或如实失败。 |

### 2. 单次任务的自验收循环

1. **定位**：读本方案、体验审查、当前任务记录和相关源码；确认 Git 工作区已有改动、当前运行中的程序、旧候选与新候选哈希。列出本次要关闭的 A 节点子项，不顺手改其他阶段。
2. **先写反例**：针对该任务至少列出正常、边界、失败三类输入。推荐要有错季、节日/天气冲突与离线；窗口要有长文案、低工作区和隐藏返回；动效要有未知天气、减少动态和安全提醒。
3. **实现并自动验证**：修改功能与对应测试；运行当前任务相关检查，再运行 `lint`、`typecheck`、`test`、`build`。涉及 Rust 或桌面权限时运行相应原生检查。失败项保留日志和复现步骤，不能通过放宽断言来取得绿色结果。
4. **看真实作品**：涉及窗口、排版、颜色或动效时，以同一候选在 Windows 原生窗口检查短诗/长诗、浅色/深色、小窗/阅读窗、横排/竖排、静态/动态的适用组合。至少记录一张可读的界面图；动画节奏用短录屏，不能只凭静态图推断。界面中每个主要操作须可键盘到达、焦点可见。
5. **绑定证据**：记录源码版本、EXE SHA-256、测试命令与结果、隔离资料条件、原生环境、图片/视频/日志路径。模拟天气必须明确写“隔离演练”，不能把它当真实当地天气。候选哈希变化后，受影响的性能、安装和视觉证据须重新采集。
6. **逐条判定**：对第四节该任务的每一条通过条件标记“通过/失败/未测”，解释依据。只要有阻断失败或必要证据未测，整体不得写“通过”；下一位 AI 先处理失败或缺口，再推进依赖任务。

### 3. 美术与使用的可观察退出条件

这些检查把“好不好看、好不好用”中可由 AI 复核的部分具体化；审美偏好仍留给 T11 真人决定。

| 关注点 | AI 必查的具体问题 | 通过所需证据 |
|---|---|---|
| 第一眼信息量 | 小窗里是否首先看见完整诗句、题名作者和一条理由？节日/天气/节气是否只占一条情境提示？ | 代表性短/长内容截图；主诗句、继续读、收藏、收起无需滚动即可找到；无横向溢出。 |
| 竖排是否真的合适 | 竖排是否只是换了方向，却让长题名、词句或按钮拥挤？横竖排正文是否逐字一致？ | 五言、七言、词、长诗和特殊标点的双布局截图与文本一致性测试；读屏顺序不变。 |
| 环境是否抢戏 | 场景是否帮助理解诗意，而非持续吸引视线？雨雪是否被误认作当地实时天气？ | 场景数据和文案对照表、浅深色图、代表性短录屏；每画面最多一个主意象和一个小组件；诗文和操作静止。 |
| 放大后是否仍好用 | 小/中/大诗笺与可调整阅读窗能否往返？字号是否独立调整？ | 原生窗口状态和低工作区检查；展开/缩小不重新推荐、不丢收藏，窗口始终可找回。 |
| 每天是否值得打开 | 今天的诗是否与节日 > 真实天气 > 节气相符？不能匹配时是否诚实降级？重复是否过快？ | 120 首目录的情境矩阵和 30/60/90 天模拟、异常样本清单；具名内容审读另由 H1 完成。 |
| 是否打扰 | 自动出现是否抢正在输入的焦点？全屏或演示时是否抑制？收起后是否容易找回？ | 原生 Windows 焦点/托盘/全屏观察；不具备真实系统条件时明确“未测”。 |
