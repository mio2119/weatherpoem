# WeatherPoem 完整修改方案：AI 任务、自验收节点与签收条件

版本：1.5（2026-10-15）。用途：作为本轮改版的单一执行导航，可直接交给后续 AI 分批实施；具体技术细节以 [原执行方案](./PRODUCT_REDESIGN_EXECUTION_PLAN_2026-10-12.md) 为准，问题依据见 [体验审查](./PRODUCT_EXPERIENCE_AUDIT_2026-10-12.md)，**实际完成状态**以 `review/redesign/Txx` 的证据和当前源码为准。文档中的目标不是已完成声明；若资料冲突，先核实再修改记录，不得挑选最有利的“通过”说法。

## 1. 产品合同与本轮边界

目标用户是有文化基础、却在大学日常中较少接触传统文化的学生。产品要让人打开电脑后自然遇见一首与当天生活有关的诗，第一眼只见诗句与一条可信的关联理由；想深入时再看全文、注释、背景、今日联系和出处。主推荐优先级：**传统节日 > 当地真实天气 > 节气**。重大事件是以后由人审核的策展能力，本轮不做自动抓取新闻、即时事件配诗或无来源的 AI 即兴编诗。

本轮要保留并改好现有 Vue 3 + TypeScript + Tauri 2 应用，不迁移框架、不从零重画。`E:\weatherpoem` 是开发目录；`D:\纯净工作台` 只作为最终控制与独立审计面。旧 `0.2.0` 候选、哈希及其证据留作基线，不把旧候选的通过报告移到新候选。七天正式长测已按项目决定跳过，RQT-13 完整门禁继续是 `partial`。

本轮体验原则：**少而清楚、随时可退、情境真实、动而不扰、文化内容可核查**。错误城市、明显错季、不实天气、丢失收藏/设置、抢焦点、遮挡安全提醒，比画面美观更优先修复。

## 2. 目标界面与设计决定

| 状态 | 必有内容和行为 | 不应发生 |
|---|---|
| 默认小诗笺 | 约 392×320 逻辑像素起试排，可在小/中/大尺寸间切换；突出完整节选、题名作者、一句理由；继续读、收藏、收起可发现；情境信息压为一条 | 用很小的字硬塞内容；自动抢走正在输入的焦点；长题名/理由盖住操作 |
| 展开阅读 | 约 560×720 起试排，允许调整尺寸与最大化；全文优先，注释/背景/今日联系按需展开，出处常驻可找；能回到来处 | 展开后重新推荐、收藏状态丢失、长页找不到返回 |
| 竖排选项 | 初次默认横排，用户可选诗文从上到下、列从右到左；只改变诗文的视觉排法，辅助信息仍横排；保存偏好 | 宣称竖排必然省空间；删字、错序、挤压按钮；读屏顺序随视觉顺序乱掉 |
| 诗境和小组件 | 基于当天日历、真实可用天气与**本首诗的意象**选择一个主意象、最多一个小组件；先做静态，再增加低对比局部动效 | 缓存/离线天气被画成当地实时雨雪；背景压过诗句；多个装饰和信息堆在同一小窗 |
| 安全/撤回/故障 | 用独立的清晰提示和可执行的处置入口；普通诗境暂停 | 预警被诗句或动效弱化；撤回作品仍可通过收藏继续读原文；资料故障被误显示为空资料 |

美术沿用现有暖纸色、宋体阅读、朱砂点缀作为起点，先做**同一首诗的静态 A/B 画面**：A 更克制、B 有一个情境意象；横排/竖排和浅色/深色各看真实内容。只有读字、信息层级和意义对应通过后才做动效。AI 可以测遮挡、对比度与节奏，不能替项目方判断“雅致、每天看不腻”；视觉定稿在 H1 由真实使用者和项目方决定。

## 4. AI 每一批必须执行的自验收循环

1. **划定范围**：读取本文件、原执行方案对应 T 项、体验审查、`review/redesign/Txx`、相关源码/测试；检查 Git 工作区和运行中的候选。写明本批只关闭哪个 A 节点子项、依赖是否具备、哪些事项不做。
2. **先定反例**：至少列一个正常、一个边界、一个失败输入及明确预期。可自动化缺陷先保留能复现的红测，修复后同测转绿；视觉缺陷保存同场景的修改前后画面。不能删掉失败样本或放松断言。
3. **最小实现**：只在相关组件、服务、样式和测试中增量修改；不迁移栈、不改旧发布证据、不把真实用户资料作为测试数据。新增素材/依赖先核许可、来源、体积和资源成本。
4. **分层验证**：定向测试 → `npm.cmd run lint` → `npm.cmd run typecheck` → `npm.cmd run test` → `npm.cmd run build`；相关内容/推荐/无障碍检查按变更追加。涉及桌面行为时才在获准的隔离账户或资料中做原生观察；静帧不能证明动画，浏览器不能证明 Windows 焦点和读屏。
5. **保存原始证据**：记录命令、退出码、场景输入、截图/短录屏、原始资源样本与日志、源码 commit、EXE/安装包 SHA-256。隔离天气和合成文本要在画面及记录中注明，不当作真实当地数据或作品原文。
6. **逐条签收**：每一条验收条件分别写“通过 / 失败 / 未测”，给出证据路径和下一动作；任一必需项失败或未测，整项只可写“失败/部分通过”。当哈希改变，旧原生、性能和安装报告不得自动继承。

### 必查视觉/使用场景

- 普通短诗、长题名、最长节选与理由；小/中/大窗、阅读窗；浅/深色、横/竖排与大字号。
- 节日和天气冲突、节气同日、鲜活雨雪/晴/夜、缓存/离线/未知、不匹配天气；安全预警与内容撤回。
- 首次设置失败与重试、收藏再找回、阅读后返回、低屏高滚动、键盘路径、减少动态和隐藏后停机。
- 每个适用组合核对文字内容、主操作可达、焦点可见、事实与意象一致、无横向溢出；代表动态另看短录屏。采用成对覆盖时列出未覆盖组合，不用一张正常诗截图代表全矩阵。

### 立即阻断的失败

错误城市或不实天气；明显错季且无可解释的节日例外；未确认地丢失设置/收藏；内容撤回后仍展示原文；自动抢焦点或全屏演示被打断；安全正文、诗句、返回或主要操作不可读/不可达；减少动态或隐藏后仍持续循环；当前候选的性能/安装门禁失败。出现时先修复或报告失败，不做外观粉饰、也不进入发行签收。

## 7. “完成”的四种不同含义

1. **某子项代码完成**：功能和对应自动反例通过，只能报告该子项，不等于整个 A 节点通过。
