# WeatherPoem 完整修改方案：AI 任务、自验收节点与签收条件

版本：2.0（2026-10-15）。用途：作为本轮改版的单一执行导航，可直接交给后续 AI 分批实施；具体技术细节以 [原执行方案](./PRODUCT_REDESIGN_EXECUTION_PLAN_2026-10-12.md) 为准，问题依据见 [体验审查](./PRODUCT_EXPERIENCE_AUDIT_2026-10-12.md)，**实际完成状态**以 `review/redesign/Txx` 的证据和当前源码为准。文档中的目标不是已完成声明；若资料冲突，先核实再修改记录，不得挑选最有利的“通过”说法。

## 1. 产品合同与本轮边界

目标用户是有文化基础、却在大学日常中较少接触传统文化的学生。产品要让人打开电脑后自然遇见一首与当天生活有关的诗，第一眼只见诗句与一条可信的关联理由；想深入时再看全文、注释、背景、今日联系和出处。主推荐优先级：**传统节日 > 当地真实天气 > 节气**。重大事件是以后由人审核的策展能力，本轮不做自动抓取新闻、即时事件配诗或无来源的 AI 即兴编诗。

本轮要保留并改好现有 Vue 3 + TypeScript + Tauri 2 应用，不迁移框架、不从零重画。`E:\weatherpoem` 是开发目录；`D:\纯净工作台` 只作为最终控制与独立审计面。旧 `0.2.0` 候选、哈希及其证据留作基线，不把旧候选的通过报告移到新候选。七天正式长测已按项目决定跳过，RQT-13 完整门禁继续是 `partial`。

本轮体验原则：**少而清楚、随时可退、情境真实、动而不扰、文化内容可核查**。错误城市、明显错季、不实天气、丢失收藏/设置、抢焦点、遮挡安全提醒，比画面美观更优先修复。

## 2. 目标界面与设计决定

| 状态 | 必有内容和行为 | 不应发生 |
|---|---|
| 默认小诗笺 | 约 392×320 逻辑像素起试排，可在小/中/大尺寸间切换；突出完整节选、题名作者、一句理由；继续读、收藏、收起可发现；情境信息压为一条 | 用很小的字硬塞内容；自动抢走正在输入的焦点；长题名/理由盖住操作 |
| 展开阅读 | 约 560×720 起试排，允许调整尺寸与最大化；全文优先，注释/背景/今日联系按需展开，出处常驻可找；能回到来处 | 展开后重新推荐、收藏状态丢失、长页找不到返回 |
| 竖排选项 | 初次默认横排，用户可选诗文从上到下、列从右到左；只改变诗文的视觉排法，辅助信息仍横排；保存偏好 | 宣称竖排必然省空间；删字、错序、挤压按钮；读屏顺序随视觉顺序乱掉 |
| 诗境和小组件 | 基于当天日历、真实可用天气与**本首诗的意象**选择一个主意象、最多一个小组件；先做静态，再增加低对比局部动效 | 缓存/离线天气被画成当地实时雨雪；背景压过诗句；多个装饰和信息堆在同一小窗 |
| 安全/撤回/故障 | 用独立的清晰提示和可执行的处置入口；普通诗境暂停 | 预警被诗句或动效弱化；撤回作品仍可通过收藏继续读原文；资料故障被误显示为空资料 |

美术沿用现有暖纸色、宋体阅读、朱砂点缀作为起点，先做**同一首诗的静态 A/B 画面**：A 更克制、B 有一个情境意象；横排/竖排和浅色/深色各看真实内容。只有读字、信息层级和意义对应通过后才做动效。AI 可以测遮挡、对比度与节奏，不能替项目方判断“雅致、每天看不腻”；视觉定稿在 H1 由真实使用者和项目方决定。

## 4. AI 每一批必须执行的自验收循环

1. **划定范围**：读取本文件、原执行方案对应 T 项、体验审查、`review/redesign/Txx`、相关源码/测试；检查 Git 工作区和运行中的候选。写明本批只关闭哪个 A 节点子项、依赖是否具备、哪些事项不做。
2. **先定反例**：至少列一个正常、一个边界、一个失败输入及明确预期。可自动化缺陷先保留能复现的红测，修复后同测转绿；视觉缺陷保存同场景的修改前后画面。不能删掉失败样本或放松断言。
3. **最小实现**：只在相关组件、服务、样式和测试中增量修改；不迁移栈、不改旧发布证据、不把真实用户资料作为测试数据。新增素材/依赖先核许可、来源、体积和资源成本。
4. **分层验证**：定向测试 → `npm.cmd run lint` → `npm.cmd run typecheck` → `npm.cmd run test` → `npm.cmd run build`；相关内容/推荐/无障碍检查按变更追加。涉及桌面行为时才在获准的隔离账户或资料中做原生观察；静帧不能证明动画，浏览器不能证明 Windows 焦点和读屏。
5. **保存原始证据**：记录命令、退出码、场景输入、截图/短录屏、原始资源样本与日志、源码 commit、EXE/安装包 SHA-256。隔离天气和合成文本要在画面及记录中注明，不当作真实当地数据或作品原文。
6. **逐条签收**：每一条验收条件分别写“通过 / 失败 / 未测”，给出证据路径和下一动作；任一必需项失败或未测，整项只可写“失败/部分通过”。当哈希改变，旧原生、性能和安装报告不得自动继承。

### 必查视觉/使用场景

- 普通短诗、长题名、最长节选与理由；小/中/大窗、阅读窗；浅/深色、横/竖排与大字号。
- 节日和天气冲突、节气同日、鲜活雨雪/晴/夜、缓存/离线/未知、不匹配天气；安全预警与内容撤回。
- 首次设置失败与重试、收藏再找回、阅读后返回、低屏高滚动、键盘路径、减少动态和隐藏后停机。
- 每个适用组合核对文字内容、主操作可达、焦点可见、事实与意象一致、无横向溢出；代表动态另看短录屏。采用成对覆盖时列出未覆盖组合，不用一张正常诗截图代表全矩阵。

### 立即阻断的失败

错误城市或不实天气；明显错季且无可解释的节日例外；未确认地丢失设置/收藏；内容撤回后仍展示原文；自动抢焦点或全屏演示被打断；安全正文、诗句、返回或主要操作不可读/不可达；减少动态或隐藏后仍持续循环；当前候选的性能/安装门禁失败。出现时先修复或报告失败，不做外观粉饰、也不进入发行签收。

## 7. “完成”的四种不同含义

1. **某子项代码完成**：功能和对应自动反例通过，只能报告该子项，不等于整个 A 节点通过。
2. **工程改版完成**：A0–A10 的适用必需条件均对**同一当前候选**成立，并有独立审计证据。
3. **体验验收完成**：工程改版完成，且 H1 的真实用户、具名内容审核和项目方视觉决定齐备。
4. **校园试点或公开发布可行**：仍须另过原项目的法律、签名、安装、运营与试点门禁。跳过七天长测时，相关完整 RQT-13 不得改为通过。

当前仅能如实称“改版正在进行、多个自动/隔离子项已有证据”；不能称工程改版、体验验收或对外发布完成。

## 8. 给 AI 的验收证据清单

第 3 节定义目标和退出条件，本节定义签收时必须拿得出的证据。每批仍只关闭一个可验证子项；表中“原生”是指当前源码生成的具名 Windows 候选，不是旧 `0.2.0` 或浏览器预览。没有权限运行原生场景时可继续做代码与隔离测试，但相应节点保持部分通过。

| 节点 | 自验收时必须提交 | 不能替代它的证据 |
|---|---|---|
| A0 基线 | Git 状态、旧 EXE/安装包/清单哈希、E01–E16 对应 T 项、现有场景与未测清单 | 只写“旧版正常”或用新截图覆盖旧基线 |
| A1 每日状态 | 注入本地时钟的跨日/凌晨/重复打开测试；重启与历史迁移记录；隔离资料的原生托盘/唤醒走查 | 单次当天打开、UTC 日期测试或只看诗笺文字 |
| A2 推荐 | 节日优先与错季反例、120 首理由全文扫描、30/60/90 天多情境模拟的原始结果、反馈撤销测试；人工文案审读单列 | 调权重、几个正例或 AI 自称“贴合” |
| A3 设置资料 | 无结果城市、旧资料迁移、写入失败重试、损坏记录不覆盖、清除失败回滚测试；隔离原生 SQLite/WebView2 与启动项状态走查 | 浏览器 localStorage 成功或在真实用户资料上试错 |
| A4 窗口 | 自动/手动焦点、全屏保守避让、四种窗口状态、多屏/低屏高/混合 DPI 的原生操作记录和窗口边界 | Tauri 模拟接口、静态配置或单张窗口截图 |
| A5 小诗笺 | 短诗、长题名、最长节选与理由、节日/离线/安全的浅深色画面；关键操作和低屏高可达性记录 | 只有理想长度的一首诗、仅 CSS 尺寸推断 |
| A6 排版 | 五言、七言、词、长诗及合成标点边界的逐字对照；横竖/三档字号/偏好重启；原生读屏顺序 | 竖排看起来像对了或浏览器可访问树可见 |
| A7 诗境 | 场景输入—推荐理由—画面三联对照、浅深色静帧、动态短录屏、减少动态/隐藏停机、同机同诗 60 秒静动资源原始样本与素材台账 | 静态图推断动画节奏、旧哈希性能报告或把隔离天气称为实况 |
| A8 深读 | 从诗笺及收藏两个来处完成全文、注释、来源、收藏/取消、返回和撤回的端到端记录；内容抽样表 | 单个页面组件测试或未署名的文化准确性声明 |
| A9 系统 | 当前候选的 Windows 10/11、实际缩放、键盘/读屏、故障、在线/离线准备和 CPU/内存矩阵；每项列设备与样本 | 计划文件通过、合成在线数据或另一 EXE 的资源报告 |
| A10 交付 | 全量命令退出码、Rust 检查、新 portable/NSIS/MSI/NOTICE/清单哈希、安装与升级记录、发行核验和工作台独立报告 | 把内部调试 EXE 当发行包、复制旧报告或只执行前端构建 |
| H1 人审 | 6–8 名目标用户的无讲解任务和多日接触记录、15–20 首逐首具名审校、项目方最终视觉与试用决定 | AI 自评分、自动截图、模拟受访者或匿名“已审核” |

### 签收规则

1. **子项通过**要求实现、正常/边界/失败反例、相应层级的观察与可定位证据同时存在；一张截图、一次绿色测试或说明文字均不能单独覆盖整个节点。
2. **节点通过**要求本节点所有必需子项对同一当前源码或候选成立；任何必需子项失败、未测、证据哈希不符，节点只可记“失败”或“部分通过”。旧报告保留历史价值，但不能因新候选出现而自动续期。
3. **审美签收**分两层：AI 验文字对比度、遮挡、读序、动效停机与资源；真实使用者和项目方验“是否愿意每天看”“是否累”和诗境是否得体。若多日接触暴露持续分心或视觉疲劳，即使 A5–A7 自动项通过，也应回到静态/更弱动效方案，H1 不签收。
4. **资料与安全先于装饰**：错误城市、不实天气、明显错季、误丢资料、撤回后泄露原文、预警被弱化、自动抢焦点均为阻断；出现时不进入下一批美术或发行签收。
5. **门禁不能用改日期通过**：试点计划、范围、批准、当前候选和运行报告各有独立语义。检查器因过期或不一致失败时，先判断缺的是新证据还是人类决定；未取得所需决定，就保留失败与下一责任方。
