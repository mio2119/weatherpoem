# WeatherPoem 完整修改方案：AI 任务与验收总纲

版本：1.2（2026-10-14）。本文件是给项目方和执行 AI 的总入口；逐条技术细则以 [T00–T11 执行方案](./PRODUCT_REDESIGN_EXECUTION_PLAN_2026-10-12.md) 为准，问题依据以 [产品体验审查](./PRODUCT_EXPERIENCE_AUDIT_2026-10-12.md) 为准，最新完成状态以 `review/redesign/Txx_*.md`、证据和当前 Git 状态为准。若三者不一致，先核对，不自动采用最乐观的说法。

## 1. 要做成什么

面向有一定文化基础、但在大学日常中缺少传统文化接触机会的学生。每天打开电脑时，以低打扰的小诗笺自然遇见一首诗；推荐依据按**传统节日 > 当地真实天气 > 节气**排序，重要事件留给人工策展和审核，不抓取实时热点直接推荐。第一眼只看完整节选、题名作者、一句可信的关联理由和必要操作；主动展开后才看全文、注释、背景、今日联系与出处。

产品体验目标是：诗句是主角；情境美术帮助理解，不抢注意力；收起、找回、放大、缩小都由用户控制；无天气、无合适作品、系统故障与安全提醒时诚实降级。不能为了“国风”把小窗做成信息墙，也不能为了容纳内容把字体缩到难读。

### 已确定的设计合同

| 方面 | 修改方案 | 必须守住的边界 |
|---|---|---|
| 窗口 | 自动出现为小诗笺；主动“继续读”进入可调整尺寸的阅读窗；小/中/大诗笺尺寸与正文字号分别设置，返回后不重新推荐。 | 自动出现不抢正在输入的焦点；全屏/演示时保守避让；安全长文案独立适配，不塞进短卡。 |
| 排版 | 默认横排；诗文可切为从上到下、列从右到左的竖排，保留同一语义文本与读屏顺序；长内容可增高或回退横排。 | 竖排不是必须省空间；不删句、不拆断句、不缩小字号硬塞。辅助文案和操作保持横排。 |
| 信息层级 | 主诗句 > 题名作者 > 一句理由 > 操作 > 情境元信息；第一眼的节日/天气/节气收为一条提示。收藏、继续读、收起可见；换诗与反馈降为次级操作。 | 关键操作不因美术或长内容不可达；天气新鲜、缓存、不可用的措辞不同。 |
| 美术与动效 | 沿用暖纸色、宋体阅读和朱红强调作为起点；每屏最多一个主意象、一个有含义的小组件。先做静态，再给雨、雪、晴、夜及相关节日加入低对比局部动效。 | 不把诗中天气画成当地实况；未知天气不画实时雨雪；诗文与按钮不动；减少动态、隐藏/最小化、安全提醒时停掉循环装饰。素材有来源、授权和体积记录。 |
| 深读 | 全文在前；注释、背景、今日联系、出处按需展开；收藏后有稳定复访入口。 | 来源不足不编版本；内容撤回后不能经收藏或阅读页继续正常展示；文化准确性由具名人员审核。 |

初始尺寸和字号只是试排参数：诗笺约 392×320 逻辑像素，阅读窗约 560×720，诗句约 22–26px，理由/操作约 13–14px。真实作品、低工作区、系统缩放和目标用户观察有冲突时，以可读性和可达性为准调整，并记录原因。

## 2. 总体顺序与阶段门禁

每次只交给 AI **一个任务编号中的一个可独立验收子项**。可以在上游尚未全部签收时做隔离研发，但不能宣布依赖它的整项通过；正式新发行候选 T10 必须等 A0–A9 的适用子项全部签收。

| 阶段 | 任务 | 产物 | 进入下一阶段的条件 |
|---|---|---|---|
| 基础可信 | T00–T03 | 旧候选基线、跨日/历史、推荐规则、首次设置与异常反馈 | 日期、城市、天气、设置和推荐没有已知阻断缺陷；A0–A3 的适用条件及证据逐项核对。 |
| 日常使用 | T04–T06、T08 | 窗口状态、小诗笺、横竖排、字号、深读与收藏路径 | 原生窗口与真实长短内容可用；展开/返回不丢状态；浏览器截图不能代替原生缩放、焦点和读屏。 |
| 诗境美术 | T07 | 场景映射、浅深静帧、短录屏、动/静资源对照、素材台账 | 情境真实、不遮字、不持续抢注意力；减少动态/隐藏停机及性能目标有原始证据。 |

## 3. 各任务的 AI 自验收节点

“通过”需要同时有实现、正常场景、边界/失败反例和该节点要求的证据；缺少必要原生或真人证据时只能记“部分通过/未测”。详细输入与异常路径见执行方案第四节。

| 任务 / 节点 | AI 要改或补什么 | 可核查的验收条件 |
|---|---|---|
| T00 / A0 基线 | 核对旧发布物哈希、Git 变更、运行中的候选及 E01–E16 问题映射。 | 旧 EXE/清单未改；每个问题有任务归属；组件、浏览器、Windows 原生、人工证据分开记。 |
| T01 / A1 日期与历史 | 本地自然日统一、跨日刷新、每天换一次、原诗与替换诗的展示历史、旧资料迁移。 | 北京时间 00:00/07:59/08:00/23:59 与其他时区反例正确；同日重开不重推，次日更新；旧浏览器/SQLite 当天跨季已看作品可继续读但不被伪称今日天气匹配；收藏和历史不丢。 |
| T02 / A2 推荐 | 先排除明显错季，再按节日 > 天气 > 节气排序；完整中文理由；作品/作者多样性；负反馈可撤销。 | 冬雨不直接推早春诗；天气不可用不虚构实况；全 120 首理由无英文枚举、双标点、半句；30/60/90 天多情境模拟记录不同作品数和重复间隔，优于旧晴天 60 天仅 23 首基线；单次“不贴合”不过度长期惩罚整类作品。 |
| T03 / A3 首次设置 | 城市无结果与最终城市确认、设置草稿/保存、系统自启动反馈、桌面资料库故障恢复。 | 搜索未选中不暗用北京；设置→收藏→返回不静默丢草稿；保存失败不报全成功；SQLite 故障不悄悄切到空白资料；隔离旧资料升级、失败回滚和重试通过。 |
| T04 / A4 窗口 | 小诗笺/阅读/设置/安全状态、焦点、尺寸、工作区、托盘、全屏避让。 | Windows 原生自动展示不夺焦点；主动打开可键盘操作；小↔大不换诗不丢收藏；多屏、混合 DPI、低工作区仍可找回；安全长文案完整。 |
| T05 / A5 小诗笺 | 精简首屏层级，保留完整节选、题名作者、短理由、继续读/收藏/收起；折叠次级操作。 | 短诗、最长节选、长题名及 40 字理由边界在小/中/大、浅/深、横/竖适用组合中无横向溢出、遮挡或丢字；节日、离线、安全状态准确；主操作可见或在极低工作区可安全到达。 |
| T06 / A6 排版与字号 | 横竖排切换、字号档位、偏好持久化和超界回退。 | 五言、七言、词、长诗、特殊标点逐字一致；竖排列序正确、读屏自然；大字号/小窗下按钮可达；隐藏/重启后偏好保留。125/150/200% 实际 Windows 缩放在 A9 原生核验。 |
| T07 / A7 诗境 | 节日、雨、雪、晴、夜、未知天气及安全状态的场景映射与轻动效。 | 画面与推荐/天气事实一致，未知/缓存天气不冒充实时；文字与焦点不动、不被遮；减少动态、隐藏、安全时循环停止；同机同诗 60 秒动效相对静态平均 CPU 增量 ≤2 个百分点、工作集 P95 增量 ≤20 MiB，保留原始样本。 |
| T08 / A8 深读 | 全文、注释、背景、今日联系、来源、返回路径、收藏找回和撤回控制。 | 从诗笺/收藏进入后可回原处；收藏同步；长页焦点与返回可达；撤回作品不可经其他入口正常显示；15–20 首不同体裁形成待人工内容核对清单。 |
| T09 / A9 真机 | 键盘、读屏、Windows 10/11、100/125/150/200% 缩放、低工作区、混合 DPI、多屏、故障和性能。 | 主要路径键盘可完成且焦点可见；适用设备组合无阻断；冷启动 P95 ≤2s、首帧 P95 ≤300ms、离线准备 P95 ≤2s、在线准备 P95 ≤5s、托盘空闲 CPU <0.2%/内存 P95 <100 MiB。在线样本未出现则记“未测”，不填通过。 |
| T10 / A10 新候选 | 在上游通过后独立构建 portable/NSIS/MSI，刷新哈希、NOTICE、安装/升级、性能、就绪与发行证据。 | `lint`、`typecheck`、`test`、`build`、`check` 与相关 Rust 检查通过；新报告绑定新候选哈希；`release:verify` 通过；最后从 `D:\纯净工作台` 运行 `weatherpoem-verify`。七天长测既已跳过，RQT-13 仍只能是 `partial`。 |
| T11 / H1 真人 | 邀请 6–8 名目标用户无讲解完成首次设置、十秒读诗、解释理由、深读、收藏找回、排版调整和收起找回；具名审校诗文。 | 至少 80% 核心任务无提示完成，并保留实际分子/分母；记录卡点与原话；15–20 首逐首记录底本、审校人、问题和修订；项目方对视觉与小范围试用作 Go/No-Go 决定。AI 不代签。 |

## 4. 界面与情境的最低测试矩阵

同一候选下至少取普通短诗、最长节选、长题名、五言、七言、词、长诗和特殊标点；按适用性组合横/竖排、小/中/大字号与窗口、浅/深色、默认/低工作区。情境至少包括节日与天气冲突、新鲜雨雪、缓存、离线/未知、系统减少动态、安全预警、内容撤回、资料库故障。每组记录预期数据、实际可见文案、窗口尺寸、文字和操作是否完整、键盘可达性。可采用成对组合减少数量，但未覆盖项列出，不得以一张普通诗截图代替全矩阵。

视觉验收分两层：AI 能查字是否清楚、是否遮挡或溢出、文本是否一致、操作是否可达、动效是否停机；“雅致、不疲劳、愿意每天见到”必须由目标用户与项目方看真实窗口和短录屏后判断。节日与安全的浏览器模拟只能证明浏览器布局，不能外推为 Windows 原生 WebView2、系统缩放、读屏或真实预警通过。

## 5. AI 每批的固定自验收流程

1. **限定范围**：只选一个 T 项的一个子项，读本总纲、对应技术细则与当前 Txx 记录；先查 Git 工作区和候选是否仍在运行。不要覆盖未提交改动、旧发布物或旧证据。
2. **列出反例**：至少一个正常、一个边界、一个失败场景；写清输入、期望和证据形式。代码缺陷先用定向测试复现；视觉缺陷保存同一内容的修改前后图。
3. **最小改动**：沿现有 Vue 3/TypeScript/Tauri 2 实现，不为美术重写产品。新素材/依赖先核许可、大小与性能。异常路径与正常路径一起实现。
4. **分层验证**：相关测试先通过，再跑 `lint`、`typecheck`、全量 `test` 和 `build`；桌面/Rust 改动做对应原生检查。界面看真实作品和实际尺寸；动效看短录屏及资源原始样本；系统焦点、读屏、真实天气需原生或真实数据证据。
5. **保存证据**：记录源码提交、候选 EXE/安装包 SHA-256、隔离资料、环境、命令、输出、截图/录屏、原始样本。模拟情境明确标“隔离演练”。哈希变更后，受影响的原生/性能/安装证据重新采集。
6. **逐条判定**：每条退出条件写“通过 / 失败 / 未测”，附证据位置与下一动作。任何必需项失败或缺证时，不宣布整个 A 节点完成；不把旧候选、浏览器、组件、AI 自评分当成新原生或真人结论。

每批交付格式：`目标与不做范围｜改动文件及理由｜正常/边界/失败测试｜原生观察及环境｜视觉矩阵｜源码与候选哈希｜每条条件的通过/失败/未测｜剩余风险｜下一批唯一优先事项`，追加保存到对应 `review/redesign/Txx_*.md`。

**立即阻断**：错误城市或不实天气、明显错季、诗句/安全文字/关键按钮不可读或不可达、资料或设置静默丢失、自动抢焦点或全屏打断、撤回后继续正常展示、减少动态/隐藏时动画仍循环、当前候选性能或发布门禁失败。先修复或如实记失败，不用美术微调绕过。
