# WeatherPoem 校园试点方案

## 1. 当前边界

计划版本：`2026.07-pilot-local-v2`  
计划状态：等待真实试点负责人和隐私责任人批准  
建议规模：30—50 名年满 18 周岁的在校大学生  
记录周期：28 天

本方案选择“本地按日聚合 + 无时间戳会话计数、参与者人工复制摘要”，不建设统计
服务器，不自动上传。
这样可以先回答“是否按时送达、是否愿意深入阅读、是否打扰”等核心问题，又不为了
试点提前引入账号、设备标识、IP、精确位置或行为明细。

当前文本是可执行候选，不是已经生效的招募同意书。正式招募前必须补入真实负责人、
联系方式、投诉与退出渠道，并由试点负责人和隐私责任人具名批准。若学校要求伦理、
科研或学生工作审批，也必须先完成。

## 2. 参与者条件

- 年满 18 周岁；
- 当前为在校大学生；
- 可以不是传统文化爱好者；
- 自愿安装和使用，不因拒绝或退出受到任何不利影响；
- 知道当前安装包是未签名受控试用版；
- 能在结束时自行决定是否复制并提交本地摘要。

不招募未成年人。不同专业、年级和城市应尽量均衡，避免只从文学社团或传统文化
社群招募。

## 3. 同意文本

应用中的三项确认分别是：

1. 我已年满 18 周岁；
2. 我理解参与完全自愿，可以随时退出且不影响继续使用；
3. 我同意在本机按自然日累计本方案所列记录，并累计已结束会话与异常中断会话数。

邀请方还必须在应用外明确告知：

- 项目目的、四周安排和预计投入；
- 真实负责人、联系方式和问题投诉渠道；
- 安装包未签名及卸载方式；
- 数据不会自动上传，是否提交摘要由参与者自己决定；
- 退出、清除数据和试点结束后的处理方式；
- 严重内容错误、天气安全问题和版本撤回的通知方式。

首次设置中对天气城市请求的同意不能复用为试点同意；旧版 `anonymousMetrics`
值和 `2026.07-pilot-local-v1` 同意也不能作为新增会话测量的授权。

## 4. 数据最小集

应用只在参与者主动开始试点后记录以下“某自然日是否发生”的集合，同一天重复操作
仍只计一次：

| 本地事件 | 用途 | 摘要中输出 |
|---|---|---|
| `app-opened` | 观察应用活跃日 | 活跃天数 |
| `poem-presented` | 观察成功呈现 | 成功呈现天数 |
| `warning-suppressed` | 从应推送日排除安全暂停 | 安全暂停天数 |
| `detail-opened` | 观察深入阅读意愿 | 深入阅读天数 |
| `not-relevant` | 观察情境不贴合 | 不贴合天数 |
| `poem-replaced` | 观察主动换一首 | 换诗天数 |
| `favorite-added` | 观察主动留存内容 | 新增收藏天数 |
| 会话打开标记 | 下次启动时保守识别上次是否异常中断 | 不直接输出 |
| 正常退出/异常中断累计 | 形成已结束会话分母 | 已结束、无异常中断、异常中断会话数 |

不记录和不导出：

- 姓名、学号、手机号、邮箱、账号或参与者编号；
- IP、设备名、硬件标识、系统用户名或桌面信息；
- 具体城市、经纬度或学校；
- 诗词 ID、篇名、正文、作者或查看了哪一首；
- 操作时刻、事件顺序或逐条原始日志；
- 会话开始/结束时刻、进程号、崩溃堆栈、转储文件或错误正文；
- 收藏清单、阅读历史、反馈文本和天气响应。

## 5. 本地匿名摘要

设置 → 校园试点 → 查看可复制摘要，可以在提交前检查完整 JSON。摘要只包含：

- 计划、应用、内容和规则版本；
- 记录开始日、结束日和摘要生成日；
- 活跃、应呈现、成功呈现、安全暂停、深入阅读、不贴合、换诗和收藏的天数；
- 已结束、无异常中断和异常中断会话数；
- 送达率、深入阅读率、不贴合率和无异常中断会话率；
- 摘要生成时开机启动是否启用；
- 七个明确为 `false` 的隐私字段：自动上传、标识符、城市、作品 ID、原始事件、
  会话时间点和崩溃转储。

参与者必须主动复制并交给邀请方；应用没有统计端点，也没有后台发送队列。

指标定义：

```text
应呈现天数 = 活跃天数 - 安全暂停天数
送达率 = 成功呈现天数 / 应呈现天数
深入阅读率 = 深入阅读天数 / 成功呈现天数
不贴合率 = 不贴合天数 / 成功呈现天数
无异常中断会话率 = (已结束会话数 - 异常中断会话数) / 已结束会话数
```

分母为 0 时输出 `null`，不能写成 0%。

## 6. 保留与退出

- 记录期为开始日及其后共 28 个自然日；
- 第 29 天起停止新增，只允许参与者查看摘要；
- 计划保留上限为开始后的第 35 天；
- 应用无法在完全未运行时自行删除文件，因此第 35 天起在下一次启动时自动清除；
- 试点结束流程必须要求参与者在第 35 天前提交后点击“退出试点并删除本地记录”；
- 主设置中的“清除个人数据与设置”也会删除试点记录；
- 退出立即删除同意状态和全部聚合记录，不能恢复；
- 单纯卸载可能按安装器保护策略保留应用数据，不应替代应用内退出或清除。

## 7. 四周执行安排

| 时间 | 执行动作 |
|---|---|
| 试点前 | 批准方案；冻结版本；完成招募、同意、安装与退出演示 |
| 第 1 周 | 检查安装、自启、送达、重复弹出和明显打扰 |
| 第 2 周 | 关注情境贴合、深入阅读、不贴合与天气安全 |
| 第 3 周 | 关注内容重复、视觉疲劳、开机启动保留和主动收藏 |
| 第 4 周 | 复制本地摘要，完成结束问卷，邀请 6—10 人访谈 |
| 试点后 | 删除本地记录，汇总缺陷、指标、内容错误和 Go/No-Go |

除崩溃、错误原文、安全问题和严重表达错误外，试点中不频繁改变推荐规则。任何变更
必须记录版本和生效日期，变更前后的数据不能直接合并。

## 8. 每周简短回访

每周只询问三项，减少研究本身造成的打扰：

1. 本周是否出现未预期的重复弹出或抢焦点？若有，请描述日期和场景；
2. 本周诗笺与当天情境的贴合度为 1—5 分；
3. 本周打扰程度为 1—5 分，是否有一次具体原因？

不要在回访表收集学号、电话号码、精确位置或完整设备信息。若需联系参与者，联系表
应由批准的邀请方单独保存，不能与匿名摘要合并。

## 9. 结束问卷

建议采用 1—5 分量表，并保留两个可选开放题：

1. 诗笺出现的时机自然；
2. 每日信息量合适；
3. 视觉上不容易疲劳；
4. 推荐通常与节日、天气或节气贴合；
5. 我愿意主动打开“了解更多”；
6. 我重新接触到了一些传统文化内容；
7. 我愿意继续保留应用；
8. 我愿意继续保留开机启动；
9. 天气安全提示与诗词推荐的边界清楚；
10. 我知道如何退出并删除数据。

开放题：

- 哪一次推荐最自然地进入了你的日常？为什么？
- 哪一次让你觉得不贴合、打扰或表达不当？希望怎样改？

## 10. 半结构访谈

从不同专业、年级和使用强度中邀请 6—10 人，约 20—30 分钟：

1. 第一次看到诗笺时，你把它理解成什么产品？
2. 哪种情境最容易让你觉得“这首诗是今天的”？
3. 哪些时候你会直接关闭，哪些时候会继续读？
4. 每天一次是否合适？有没有形成疲劳？
5. 节日、天气、节气三类信息中，哪类最有价值？
6. 详情中的文化背景和当代连接是否自然？
7. 你是否担心城市、阅读或反馈数据被收集？
8. 如果继续保留，你最希望减少什么，而不是增加什么？

访谈记录使用独立研究编号，不写入应用摘要；引语用于报告前应再次确认去标识方式。

## 11. 成功标准与解释

沿用产品基线：

- 内容成功送达 ≥95%；
- 同日重复自动弹出为 0；
- 原文、作者、篇名和出处错误为 0；
- “与今天不相关” <10%；
- 深入阅读率 ≥15%；
- 四周后仍保留应用和开机启动 ≥40%；
- 认为“不明显打扰” ≥85%；
- 严重预警不当推荐为 0；
- 崩溃无感会话 ≥99.5%。

本地摘要可以直接支持送达、深入阅读、不贴合、当前自启和无异常中断会话率。
异常中断采用保守代理：上次会话未通过托盘退出完成正常结束，下次启动时即计入，
其中可能包含强制终止、系统关机或真实崩溃，不等同于崩溃堆栈诊断。重复弹出由应用
测试与每周回访共同验证；不打扰、长期保留由问卷和最终检查验证；内容错误与安全由
缺陷、事件和技术报告验证。不能用一个摘要替代全部成功标准。

## 12. 正式启动前检查

- [ ] 试点负责人和隐私责任人具名批准；
- [ ] 真实联系方式、退出和投诉渠道已写入邀请材料；
- [ ] 学校要求的伦理、科研或学生工作审批已完成或书面确认不适用；
- [ ] 候选版本、内容版本和规则版本冻结；
- [ ] 30—50 人招募范围和 18+ 条件确认；
- [ ] 安装、卸载、退出和数据清除由非开发人员走查；
- [ ] 隐私负责人批准 v2 会话计数；质量负责人验证正常退出、强制终止和恢复计数；
- [ ] 问卷、访谈、联系表和匿名摘要分开保存；
- [ ] P0/P1 响应人、内容撤回人和回滚人已指定；
- [ ] 试点结束删除与 Go/No-Go 会议日期已安排。

执行时先填写
`review/evidence/RQT-16-pilot-session-measurement-validation.template.json`，
绑定冻结候选哈希并完成五个 Windows 真机场景；全部具名批准后另存为
`review/evidence/RQT-16-pilot-consent-measurement.json`。在真实批准人与证据
存在前，`RQT-16` 必须保持 `partial`。
